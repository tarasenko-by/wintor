# Wintor

A modern, open-source BitTorrent client for Windows 11, built with WinUI 3.

Most torrent clients still look like it is 2010: dense tables, dozens of columns,
settings you get lost in. Wintor aims to feel like a native Windows 11 app —
Mica, Fluent design, sensible defaults — with no ads and no telemetry.

> **Status:** early development (v0.2). See [docs/ROADMAP.md](docs/ROADMAP.md).

## Features (so far)

- Add torrents from magnet links (prefilled from the clipboard), `.torrent` files, drag & drop,
  a double-click on a `.torrent` file or a `magnet:` link in the browser
- Choose the folder and the files to download before adding; a warning if they will not fit on the drive
- A calm table: progress bars colored by state, sortable and resizable columns, pick which ones to show,
  your own order (№)
- Status filters and colored labels in the side pane; search from the title bar
- Details pane below the table: piece map and availability, files with per-file priority, peers, trackers,
  speed graph
- Select several torrents to pause, resume, label or remove them together; right-click menu on every row
- Speed limits for everything and for each torrent; listening port, start with Windows
- Keeps seeding in the notification area when the window is closed; "download finished" notifications
- Explains problems in plain words — files deleted, disk full, no network — and resumes when you fix them
- Solid light/dark look by default, Mica or Acrylic if you like; high contrast
- English and Russian UI, plus ten more languages machine-translated and waiting for native speakers to review
  (see [Translations](CONTRIBUTING.md#translations))
- Torrents survive restarts; paused ones stay paused

## Building

Requirements:

- Windows 10 1809+ or Windows 11, with **Developer Mode** on
  (Settings → System → For developers)
- [.NET 10 SDK](https://dotnet.microsoft.com/download)
- Optional: Visual Studio 2022/2026 with the *WinUI application development* workload,
  or [WinApp CLI](https://github.com/microsoft/winappcli)

From Visual Studio: open `Wintor.sln`, pick `x64` (or `ARM64`), set **Wintor.App (Package)** as startup and press F5.

From the command line:

```powershell
winapp run src\Wintor.App
```

Wintor keeps running in the notification area when its window is closed. To quit it from a terminal:

```powershell
wintor --quit
```

Tests:

```powershell
dotnet test Wintor.sln -p:Platform=x64
```

Icons and the logo are generated by `tools/Wintor.IconTool` — see [AGENTS.md](AGENTS.md#icons).

## Project layout

| Project | What it is |
|---|---|
| `src/Wintor.App` | WinUI 3 app: windows, pages, view models, localized strings |
| `src/Wintor.Core` | Engine-independent models, `ITorrentEngine`, formatting helpers |
| `src/Wintor.Engine.MonoTorrent` | `ITorrentEngine` implementation on [MonoTorrent](https://github.com/alanmcgovern/monotorrent) |
| `tests/*` | xUnit tests; `tests/ui` — UI Automation smoke tests that run in the background |
| `tools/Wintor.IconTool` | Imports Hugeicons, outlines them for WinUI, renders the logo |

The UI only talks to `ITorrentEngine`, so the BitTorrent engine can be replaced
without touching the app. More in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Translations

UI strings live in `src/Wintor.App/Strings/<language>/Resources.resw`. Twelve languages so far; ten of them
are machine-translated and need a native speaker's review — see [CONTRIBUTING.md](CONTRIBUTING.md#translations)
for the list and how to help.
